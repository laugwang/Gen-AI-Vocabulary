Retrieval-Augmented Generation (RAG)

入門

一句話定義

RAG 是在模型回答前，先從外部資料庫找出相關段落放進 prompt，讓模型「有所根據」地回答。

白話比喻

閉卷考試 vs. 開書考試。一般 LLM 是閉卷，只能憑記憶；RAG 讓模型變成開書考，先翻到相關頁面再作答。

運作原理

  1. 把文件切成段落（chunk），每段算出 embedding 存進向量資料庫。
  2. 使用者提問時，把問題也轉成 embedding。
  3. 找出最相似的前 k 段（例如 k = 3）。
  4. 把這些段落和問題一起組成 prompt 交給 LLM。
  5. LLM 根據提供的段落回答，並可以附上出處。

小例子

一個 RAG 的 prompt 長這樣：

請只根據以下資料回答問題，若資料中沒有答案，請回答「資料中沒有提到」。

[資料 1] 本課程期末報告佔 40%……
[資料 2] 作業遲交可在隔天 16:00 前補交……

問題：作業可以遲交嗎？

常見誤解

  • 誤解：用了 RAG 就不會有幻覺。 其實：檢索到錯的段落、或模型沒遵守指示時，仍會答錯。
  • 誤解：RAG 會讓模型「學會」新知識。 其實：模型參數沒有改變，只是當下多看了資料；要改變模型本身需要微調。
